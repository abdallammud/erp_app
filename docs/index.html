Planning phase

A multi-tenant ERP for NGOs — not just WARDI

This is the working plan for a fully-featured, multi-module Enterprise Resource Planning system for humanitarian and development organizations — HRM, Finance, Procurement & Logistics, and Programs — built once and reusable across many NGOs, not custom-built for a single one. It will be implemented in Laravel; this documentation set is what that build will follow.

What this planning set is built from

Four source documents were read in full and synthesized into this plan. They are treated as incomplete drafts, not a finished spec — this set fills the gaps, resolves overlaps, and generalizes anything that was written for one organization only.

DocumentWhat it isHow it was used
Terms of Reference — WARDI RDI WARDI's official ToR for a phased ERP (HRM → Finance → Procurement & Logistics → Programs), single-sourced to one vendor, 90-day HRM phase. Primary source for scope, phasing logic, deliverables, and compliance requirements. Generalized: WARDI's specific offices/regions and single-org assumptions were replaced with configurable, per-tenant equivalents.
WARDI ERP Implementation Proposal (Prime Tech Solutions) A vendor's technical & financial response to the ToR — very detailed HRM feature list, security features, team structure, methodology, 11-month timeline, $180k budget. Main source for granular HRM feature checklists and the security/governance feature list in Architecture. Vendor-specific pricing/staffing was dropped; feature lists were kept and extended.
Enterprise Resource Planning (generic NGO ERP proposal, for "MARDO") A template-style ERP proposal already organized as four modules: HRM & Payroll, Finance & Donor Compliance, Logistics & Supply Chain, Beneficiary & Project Management. Confirms the four-module shape independently of WARDI, and is the main source for the Beneficiary/Programs module and the Logistics/Fleet feature list, which the WARDI ToR only sketches.
Nova Humanitarian HRM (70-page UI reference) A near-complete set of HRM screen designs: Employee Portal, Supervisor Portal, HR Admin Portal, and a Payroll Portal, for a fictional NGO. Used as the UX/functional source of truth for the HRM module — it shows working detail (fields, workflows, statuses) the text documents only describe at a bullet-point level.
The key gap this plan fills

Every source document assumes the system is built for one organization (WARDI, or the fictional MARDO/Nova). None of them address multi-tenancy — separate NGOs each running their own instance with their own staff, donors, chart of accounts, and configuration on one shared platform. That is the central design problem this plan solves; see Architecture & Multi-Tenancy.

The module map

Four functional modules sit on a shared core. Every module is usable standalone but is far more valuable integrated — a leave request affects payroll and project cost allocation; a purchase order affects the budget it draws from; a new hire needs an asset issued and a project assigned.

Module 1

HRM & Payroll

Recruitment, employee records, leave & attendance, payroll, performance, training, safeguarding, exit management. The most detailed module — see the UI reference.

What's confirmed vs. still open

Confirmed

Backend framework: Laravel (build starts after this planning phase). Four core modules. Multi-tenant, multi-org from day one. Cloud-hosted, web-based, mobile-responsive. Donor-compliance and audit-trail are first-class, not bolted on.

Still open — flagged inline

Frontend stack (Blade/Livewire vs. Inertia+Vue/React), shared-DB vs. schema-per-tenant for large customers, native mobile app timing, and which donor report templates to ship first. See Architecture and Roadmap for the recommendation and trade-offs on each.
